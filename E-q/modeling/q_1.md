
# 问题一：多模态情感特征提取与时序对齐模型

## 1. 建模目标与边界

问题一的目标是：基于附件 1 提供的 100 条英文原始视频及其转写文本，建立文本、语音、视觉三模态特征提取与时序对齐模型，并输出可以被问题二和问题三继续使用的标准化特征、有效掩码、时间映射和审计证据。

问题一不是情感极性分类或连续强度预测问题。附件 1 中的 `label` 和 `annotation` 用于样本核验和结果归档；问题二、问题三的预测模型应在附件 2 的训练/验证数据边界内另行建立。当前实现不使用外部情感数据，不修改原始视频和标签，不把附件 2 的预计算特征冒充为本问题自主提取结果。

输入目录为：

```text
E-q/dataset/attachment_1_raw_multimodal_samples/
└── mosei_raw_videos_100/
    ├── <video_id>/<clip_id>.mp4
    └── label-100.xlsx
```

每个样本的稳定主键定义为

\[
\mathrm{sample\_id}=\mathrm{video\_id}\_\mathrm{clip\_id}.
\]

禁止使用目录遍历顺序或数组下标作为跨文件主键。这样可以保证标签、视频、特征文件和后续解释结果之间能够稳定对应。

## 2. 三模态输入表示

对第 `i` 条样本，分别定义文本、音频和视觉原始序列：

\[
X_i^{(T)}=\{x_{i,r}^{(T)},\tau_{i,r}^{(T)}\},
\quad
X_i^{(A)}=\{x_{i,r}^{(A)},\tau_{i,r}^{(A)}\},
\quad
X_i^{(V)}=\{x_{i,r}^{(V)},\tau_{i,r}^{(V)}\}.
\]

其中 `T`、`A`、`V` 分别表示文本、音频和视觉，`r` 是模态内序列位置，`\tau` 是该位置对应的时间区间。文本的逐词时间戳不在附件 1 标签表中提供，因此当前实现的文本时间区间是可复现的推断时间，不是原始观测时间。

三类模态特征通过特征提取函数获得：

\[
z_{i,r}^{(m)}=f_m\left(x_{i,r}^{(m)};\theta_m\right),
\quad m\in\{T,A,V\}.
\]

其中 `\theta_m` 表示特征提取规则和固定参数。当前代码采用透明、无需外部情感数据的基线提取器；以后可以在保持输出接口不变的前提下替换为经过版本核验的 BERT、COVAERP、Facet 或其他模型。

## 3. 公共时间窗对齐模型

### 3.1 时间窗定义

将第 `i` 条视频的有效时长记为 `D_i`，统一划分为 `L=50` 个公共时间窗：

\[
I_{i,k}=\left[\frac{kD_i}{L},\frac{(k+1)D_i}{L}\right),
\quad k=0,1,\ldots,L-1.
\]

当前代码默认 `L=50`，所有样本输出形状的第二维均为 50。每个窗口都记录开始时间、结束时间和三种模态的有效状态。统一窗口的优点是接口简单、便于批量计算和后续模型输入；缺点是固定窗口不能替代真实逐词语义时间，因此文本映射必须明确标注为推断。

### 3.2 模态聚合

对模态 `m` 在第 `k` 个窗口内的原始特征集合进行聚合：

\[
h_{i,k}^{(m)}=
\operatorname{Agg}\left(
\left\{z_{i,r}^{(m)}:
\tau_{i,r}^{(m)}\cap I_{i,k}\neq\varnothing
\right\}
\right).
\]

当前实现中：

- 文本在每个窗口内对落入该窗口的词元向量取均值；
- 音频在每个窗口内对波形片段计算频谱和时域统计量；
- 视觉在每个窗口内对实际解码帧的图像统计量取均值。

为了区分真实特征、自然缺失和 padding，为每个模态定义有效掩码：

\[
q_{i,k}^{(m)}=
\mathbf{1}\left(
\exists r,\ 
\tau_{i,r}^{(m)}\cap I_{i,k}\neq\varnothing
\right).
\]

最终的掩码张量为

\[
Q_i=\left[q_{i,k}^{(T)},q_{i,k}^{(A)},q_{i,k}^{(V)}\right]_{k=0}^{L-1}
\in\{0,1\}^{L\times3}.
\]

后续模型必须使用 `Q_i` 或由其得到的 `valid_lengths`，不能仅根据特征值是否为零推断有效性。

## 4. 文本特征模型

### 4.1 词元切分

从 `label-100.xlsx` 的 `text` 字段读取英文转写文本，使用正则规则保留：

- 英文单词及带撇号的单词，如 `don't`；
- 数字；
- 标点符号。

第 `i` 条文本的词元序列记为

\[
W_i=(w_{i,0},w_{i,1},\ldots,w_{i,n_i-1}).
\]

### 4.2 固定哈希词元表示

当前基线使用 SHA-256 构造确定性的词元哈希向量，而不是依赖外部词表或外部情感数据。对词元 `w` 和盐值 `s\in\{0,1\}`，计算

\[
(j_s,\eta_s)=g(w,s),
\quad j_s\in\{0,\ldots,63\},\quad \eta_s\in\{-1,+1\}.
\]

将两个哈希位置写入 64 维向量：

\[
e(w)_{j_s}\mathrel{+}=\frac{\eta_s}{\sqrt{2}}.
\]

此外加入 8 个可复现的词法统计量：

\[
\phi(w)=
[
\text{is\_alpha},
\text{is\_numeric},
\text{is\_punctuation},
\text{length},
\text{vowel\_ratio},
\text{is\_capitalized},
\text{has\_excitation\_or\_question},
\text{relative\_position}
].
\]

因此文本单个词元的特征维度为

\[
d_T=64+8=72.
\]

### 4.3 文本时间映射

由于没有逐词时间戳，当前实现按视频有效时长对词元均匀分配时间：

\[
\hat{\tau}_{i,r}^{(T)}=
\left[
\frac{rD_i}{n_i},
\frac{(r+1)D_i}{n_i}
\right).
\]

词元的中心位置决定其所属公共时间窗。一个时间窗内存在多个词元时，对词元特征取均值。文本掩码在窗口内至少有一个词元时置为 1。该假设保证了文本特征可以和音视频共享时间窗，但不能解释为真实语音对齐；`text_token_mapping.csv` 中的 `time_source` 固定记录为 `inferred_uniform_text_timing`。

## 5. 音频特征模型

### 5.1 音频解码

使用 FFmpeg 将 MP4 中的音频流解码为：

- 单声道；
- 采样率 `f_s=16000` Hz；
- 16 位 PCM 浮点归一化波形。

记第 `i` 条样本的离散波形为 `a_i[n]`。第 `k` 个公共时间窗对应采样区间

\[
N_{i,k}=\left[
\left\lfloor I_{i,k}^{start}f_s\right\rfloor,
\left\lfloor I_{i,k}^{end}f_s\right\rfloor
\right).
\]

### 5.2 频域和时域特征

对窗口波形去均值后，使用长度不超过 1024 的离散傅里叶变换获得功率谱：

\[
P_{i,k}(f)=
\left|\operatorname{FFT}(a_{i,k})\right|^2.
\]

将 `[0,8000]` Hz 均分为 12 个频带，计算每个频带的平均能量并取 `log(1+x)`：

\[
b_{i,k,j}=\log\left(1+
\operatorname{mean}_{f\in B_j}P_{i,k}(f)\right),
\quad j=1,\ldots,12.
\]

另外提取 8 个窗口级信号统计量：

1. 均方根能量 RMS；
2. 过零率 ZCR；
3. 频谱质心；
4. 频谱带宽；
5. 85% 频谱滚降频率；
6. 归一化频谱熵；
7. 波形绝对值最大值；
8. 波形标准差。

因此音频特征维度为

\[
d_A=12+8=20.
\]

窗口内有效音频采样点少于 32 时，该窗口特征置零且掩码置为 0；否则掩码置为 1，并在 `time_mapping.csv` 中保留采样起止位置和实际采样点数。

## 6. 视觉特征模型

### 6.1 视频帧处理

使用 OpenCV 逐帧读取视频，保留原始帧率、分辨率和实际可解码帧数等元数据。每一帧缩放到 `64\times36`，并转为 RGB 和灰度表示。若容器头部记录的帧数与实际解码帧数不一致，则使用实际解码帧数重新分配公共时间窗，避免错误元数据造成视觉时间覆盖提前结束。

### 6.2 帧级特征

对每帧计算 20 维统计特征：

- RGB 三通道全图均值，共 3 维；
- RGB 三通道全图标准差，共 3 维；
- 灰度均值和标准差，共 2 维；
- Canny 边缘密度，共 1 维；
- 与上一帧灰度图的平均绝对差，作为运动强度，共 1 维；
- 中心区域 RGB 均值，共 3 维；
- 上下区域 RGB 均值差的绝对值，共 3 维；
- 左右区域 RGB 均值差的绝对值，共 3 维；
- 当前窗口帧数占容器帧数的比例，共 1 维。

总维度为

\[
d_V=3+3+2+1+1+3+3+3+1=20.
\]

对同一公共时间窗内的实际解码帧取均值，得到 `h_{i,k}^{(V)}`。窗口至少包含一帧时视觉掩码为 1，否则为 0。视频帧起止编号、窗口帧数和时间来源写入 `time_mapping.csv`。

## 7. 输出张量和文件契约

当前默认样本数为 `N=100`，时间窗数为 `L=50`，输出为：

\[
H^{(T)}\in\mathbb{R}^{100\times50\times72},
\]

\[
H^{(A)}\in\mathbb{R}^{100\times50\times20},
\]

\[
H^{(V)}\in\mathbb{R}^{100\times50\times20},
\quad
Q\in\{0,1\}^{100\times50\times3}.
\]

实际输出保存在 `E-q/q_1_output/`：

| 文件 | 建模用途 |
| --- | --- |
| `q1_aligned_features.npz` | 三模态特征、`modality_mask`、`valid_lengths` 和 `sample_ids` |
| `labels.csv` | 附件 1 标签的核对副本，不改变原始标签 |
| `sample_manifest.csv` | 样本级主键、时长、特征维度、有效窗口和状态 |
| `video_metadata.csv` | 视频帧率、分辨率、容器帧数、实际解码帧数和音频状态 |
| `time_mapping.csv` | 公共时间窗、音频采样点、视频帧和有效掩码的对应关系 |
| `text_token_mapping.csv` | 词元、推断时间区间和所属窗口 |
| `anomalies.csv` | 解码异常、帧数元数据不一致和音频覆盖不足 |
| `typical_sample.json` | 典型样本文本、标签、时间长度和词元摘要 |

| `run_summary.json` | 样本覆盖、输出形状和异常计数 |

特征文件使用 `float32`，掩码使用 `uint8`，有效长度使用整数。所有跨文件关联均通过 `sample_ids`、`video_id` 和 `clip_id` 完成。

## 8. 算法流程

```text
读取 label-100.xlsx 和视频目录
        |
建立 video_id + clip_id 主键并检查唯一性
        |
视频可读性、音频流、时长、帧率和文本字段审计
        |
文本：词元切分 -> SHA-256 固定哈希 + 词法统计 -> 均匀推断时间映射
音频：FFmpeg 16 kHz 解码 -> 窗口 FFT -> 频带能量和信号统计
视觉：OpenCV 解码 -> 缩放/颜色/灰度/边缘/运动统计
        |
按视频实际有效时长划分 50 个公共时间窗
        |
窗口聚合 + 三模态有效掩码 + 原始位置映射
        |
输出 NPZ、CSV、JSON、PNG、异常清单和运行摘要
```

脚本入口为：

```powershell
python scripts/q1_extract_features.py
```

`--max-samples N` 可用于冒烟测试，默认不指定时处理全部 100 条样本；`--steps` 可修改公共时间窗数量，但正式实验应固定配置并将配置文件随结果保存。

## 10. 建模假设与局限性

1. 假设每个视频文件对应标签表中的一个 `video_id/clip_id` 样本，主键检查用于验证该假设。
2. 假设实际可解码帧序列能够代表视频的有效视觉时间轴；容器元数据不一致时以实际解码结果为准。
3. 文本均匀时间分配是假设而非观测事实，不能用于宣称逐词级真实对齐。
4. 当前视觉特征是低维图像统计量，没有显式人脸检测、表情识别或动作识别语义。
5. 当前文本特征是固定哈希表示，不具备 BERT 等预训练语义模型的上下文表达能力。
6. 当前音频特征是窗口级频谱/时域统计，不等同于 COVAERP 或其他专用声学特征。
7. 没有在问题一中拟合训练集标准化参数，因此不会产生训练/验证泄漏；后续预测任务如需标准化，必须只用训练集拟合。
8. 当前 50 窗口公共时间轴适合作为透明基线，但若论文需要更精确的词-音-帧对齐，应补充可靠的逐词时间戳或采用有明确映射误差的强制对齐算法。

## 11. 与后续问题的接口

问题二可以使用 `q1_aligned_features.npz` 的三模态特征和 `modality_mask`，在训练阶段模拟连续窗口缺失，并在验证集选择质量门控或融合权重。问题三可以使用 `time_mapping.csv` 和 `text_token_mapping.csv` 将模态消融、时间遮挡或梯度重要性映射回文本片段、音频区间和视频帧段。

后续模型不得将问题一的哈希文本特征、低维音频统计和视觉统计直接表述为最终最优特征；它们是可审计基线。若切换到附件 2 的 `aligned_50.pkl` 或 `unaligned_50.pkl`，必须在配置中固定唯一版本，并保持训练、验证和专项测试输入接口一致。
## 12. 题目要求符合性审计与输出契约

当前实现已针对问题一的三项硬性要求补充自动审计：

- 原始样本覆盖：`sample_manifest.csv` 与 `input_file_manifest.csv` 按 `sample_id` 保存标签行、源 MP4 路径、文件存在性、文件大小、SHA-256 和 `feature_row_index`；`feature_row_index` 与 NPZ 四个数组的第一维严格对应。
- 时序可核验：`time_mapping.csv` 对每个样本固定输出 50 个窗口，记录窗口起止时间、音频采样点、视觉帧区间和三模态有效掩码；`valid_lengths` 明确定义为有效窗口计数，不假设有效窗口连续。
- 填充规则：无效窗口使用全零特征，并将对应 `modality_mask` 置为 0；下游模型必须使用掩码，不能根据特征是否为零判断有效性。
- 方法复现：`run_config.json` 记录脚本、随机种子、维度、工具和时间规则；`validation_audit.json` 自动检查样本一一对应、窗口数量、掩码、有限值、零填充和源文件摘要；`output_checksums.json` 保存输出文件 SHA-256。
