# Codex 提示词最佳实践

## 1. 总原则

提示词不是“让模型直接写完整论文”的咒语，而是一个可检查的工作契约。每次任务都明确：

1. **上下文**：题面、数据字典、已有代码、论文格式和当前小问。
2. **目标**：要回答的问题或要生成的文件。
3. **约束**：允许使用的库、时间/算力、不能修改的文件、竞赛规则和版权边界。
4. **方法要求**：先提出候选方案，再选择；给出假设、公式、算法和理由。
5. **验收标准**：测试、指标、图表、复现命令、异常情况和已知局限。
6. **输出格式**：文件路径、章节结构、表格字段或 JSON/Markdown 结构。

避免只写“请用最好的方法解决这道题”。“最好”必须被拆成可测量的目标，例如误差、稳定性、约束违背率、复杂度和解释性。

## 2. 推荐的 Codex 工作流

### 阶段 A：侦察，不修改

```text
请先只读检查项目，不要创建或修改文件。
阅读：题面、数据字典、AGENTS.md、现有代码、运行说明和最近结果。
输出：
1. 当前目录和数据流；
2. 每个小问的输入、输出和依赖；
3. 已知假设、缺失信息和潜在数据泄漏；
4. 建议的最小验证计划。
任何没有在文件中找到的事实都标记为“待确认”，不要猜测。
```

### 阶段 B：建模设计

```text
针对 [年份/题号/小问]，基于 [题面路径] 和 [数据字典路径]，
提出 2--3 个候选模型。对每个候选模型给出：
- 任务类型和目标变量；
- 符号、假设、目标函数和约束；
- 数据需求与预处理；
- 可解释性、计算成本、稳定性和失败模式；
- 如何验证以及何时不应使用。
先不要写最终论文，也不要假设不存在的字段或外部数据。
最后给出选择建议，但把选择依据写成可检验的标准。
```

### 阶段 C：实现与验证

```text
请在 [目标文件] 实现 [明确功能]，只修改与该功能直接相关的文件。
要求：
- 使用项目已有依赖；若需新增依赖，先列出理由，不要自动安装；
- 函数有类型明确的输入输出和 docstring；
- 固定随机种子，保存配置、数据切分和版本信息；
- 添加一个小规模可运行示例或测试；
- 不把数据读取、训练、评估和绘图全部堆在一个不可复用脚本里；
- 运行测试并报告命令、结果和未覆盖风险。
若输入格式或题意不足以安全实现，请停止并列出缺口。
```

### 阶段 D：论文证据链

```text
请根据 [results/表格或日志路径] 撰写 [章节] 的初稿。
每个数字只能来自给定文件；找不到来源就写“待补充”，不能估计。
区分：题面事实、建模假设、实验观察、推断结论和局限性。
检查符号、单位、编号、有效数字和图表引用一致。
同时输出“本段引用了哪些结果”和“还缺哪些证据”的清单。
```

## 3. 适合数学建模的专用约束

- 要求模型先写**假设表**和**符号表**，再写公式，防止代码先行导致含义漂移。
- 要求至少一个透明 baseline，与复杂模型在同一数据划分和指标下比较。
- 对预测问题要求区分训练、验证、测试；对时序/空间/同一对象数据要求解释切分策略。
- 对优化问题要求检查可行性、约束违背、边界解、敏感性和多目标权衡。
- 对机器学习问题要求报告数据泄漏检查、类别分布、随机种子、重复运行或置信区间。
- 对论文复现要求注明“原文明确写出”“根据代码推断”“本项目新增”，绝不伪造原文表述。
- 禁止让模型凭空生成实验结果、引用、数据来源、获奖等级或“评委偏好”。

## 4. 不推荐的提示词

- “直接帮我拿国奖”“用最先进算法解决全部问题”：目标不可检验，容易诱发堆算法和编造结果。
- “照着优秀论文改一篇”：有学术不端和版权风险，也会掩盖本题数据差异。
- “默认参数跑 K 折选最优”：可能把同一对象或未来信息泄漏到训练集，且默认参数不代表公平比较。
- “代码越复杂越创新”：复杂度不是创新，创新必须有问题动机、基线、消融或敏感性证据。

## 5. 比赛期间的合规闸门

在把当届题面、数据或论文交给任何外部服务前，先读取官方 AI 工具及成果使用规定。若规则禁止联网、外部模型或代写，应停止对应操作；本地 Codex 也不能绕过竞赛规则。资料库中的往届论文只用于赛前学习，不能直接替换当届独立分析。
