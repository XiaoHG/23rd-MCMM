# 版本分析

## 1. 版本目标与当前基线的界定

本版本不再改变问题三的预测任务定义，而是在**已冻结的预测模型输出之上**补齐“预测结果 - 模态贡献 - 局部时序证据 - 原始视频帧”的可复核解释链。解释对象应是模型在给定输入下的决策敏感性，而不是未经标注支持的真实情感因果归因；论文和图表中宜使用“模型证据”“高敏感片段”“反事实遮挡影响”等表述。

按时间戳，`E-q/q_3_output/20260925_100021_726334600/` 是当前最新的完整训练运行，应作为 v6 可视化的输入来源。该运行使用附件二 `aligned_50.pkl`（SHA-256 为 `66e867aa74bc70a844e806e5571e371c9abb4a35f9e2887ce9b4d97ff2cb8fcd`），保持 train/valid/test 为 3395/728/727 条，且 `run_attachment4=true`，因此附件四仅在固定权重后推理。`validation_audit.json` 的四项数据边界与数值检查均为 `true`，`anomalies.csv` 仅含表头，说明当前自动检查未发现非有限特征异常；这些是 v6 可以建立在其上的已验证事实。

该运行训练 50 个 epoch、共 2700 个优化步，最佳验证损失为 1.1744；valid 的 Accuracy、Macro-F1、MAE、Pearson 分别为 0.6071、0.5476、0.6521、0.5810，test 分别为 0.6726、0.5950、0.6794、0.6259。test 指标只可作为固定配置后的报告，不能据此反向选择可视化样本、解释窗口或超参数。附件四没有真值，任何视频卡片只能陈述预测、贡献和证据定位，不能声称其预测或解释“正确”。

需要特别区分：现有 `20260925_095229_511416300/` 包含训练曲线、混淆矩阵、散点图、模态贡献柱状图等论文素材，但其来源是较早的 `20260925_093119_520788600/`，并不是当前最新运行；它也没有读取 MP4 并生成关键帧叠加图。因此不能将该目录当作 v6 已完成的最终视频解释结果，最多作为图表组织形式和脚本接口参考。

## 2. 现有解释能力与 v6 缺口

当前实现已经形成三层数值解释：第一层为 `predictions_attachment4.csv` 的情感类别、连续强度和模型内部动态门控；第二层为完整模态遮挡后的 `modality_score_*` 与归一化 `modality_contrib_*`；第三层为 `evidence_mapping_attachment4.csv` 中每个模态按影响排序的局部窗口。反事实影响采用

\[
r_{i,m,k}=0.5D_{KL}(p_i\Vert p_i^{-m,k})+0.5|\hat y_i-\hat y_i^{-m,k}|,
\]

其中 \(p_i^{-m,k}\) 和 \(\hat y_i^{-m,k}\) 表示遮挡样本 \(i\) 的模态 \(m\) 在时间窗 \(k\) 后的分类概率与回归预测。窗口长度、步长均为 5，且保留每模态前 3 个非重叠窗口。该定义将分类分布变化和情感强度变化同时纳入，优于只把注意力或门控权重直接解释为贡献；但它测量的是模型的局部依赖，不构成严格的因果效应。

当前最新运行已在 32 条验证样本上完成局部遮挡忠实性诊断：高排名证据窗口平均影响为 0.05576，低排名窗口为 0.00271，前者约为后者的 20.6 倍。该结果可以支持“该批样本中排序靠前的窗口更能改变模型输出”，但样本量仅为 32，不能外推为全验证集的统计结论，也未完成多窗口大小、遮挡基线或随机种子的稳定性检验。

附件四的证据表已经为每条记录提供 `sample_id`、模态、窗口索引、影响分数、秒数、帧区间、帧率、原始文本和映射状态。以样本 `01` 为例，文本最高证据位于 aligned 索引 45--49，映射为 8.1--9.0 秒、243--269 帧（30 fps）。这证明“特征窗口到视频位置”的表格链已经存在。缺口在于：现有 `cli/q3_run.py` 只通过 OpenCV 读取 FPS 和帧数以写入映射表，没有提取关键帧、绘制时间窗或生成样本级解释卡；现有论文图也没有呈现原始画面。因此 v6 的核心新增工作应是可视化证据的生成与可核验归档，而非重训模型。

## 3. 建议的可解释可视化技术路线

建议由一个独立的、只读运行结果的脚本完成 v6 工作。脚本输入固定为最新运行目录、`evidence_mapping_attachment4.csv`、`predictions_attachment4.csv`、`run_config.json` 与附件四 MP4；不得访问标签，不得重新训练、调参或覆盖已有运行目录。输出必须新建 `E-q/q_3_output/<新时间戳>/`，并在 `source_manifest.json` 中记录源运行目录、源文件 SHA-256、脚本参数、OpenCV 版本和生成时间。

具体流程如下：

1. 读取 `evidence_mapping_attachment4.csv`，仅接受 `source_exists=true` 且 `mapping_status=mapped_to_video` 的记录；对不存在源视频、越界帧号、FPS 为零或空时间窗的记录写入新目录的 `anomalies.csv`，不以估计画面替代。
2. 使用 `cv2.VideoCapture` 打开 `source_video`，重新读取实际 FPS、总帧数与宽高；将表中的 `frame_start/frame_end` 截断到 `[0, decoded_frame_count-1]`，并记录“表内映射”和“本次解码”是否一致。对中位帧 \(\lfloor(frame_start+frame_end)/2\rfloor\) 提取原始关键帧；建议同时提取起始、中心、结束三帧，以避免单帧表情或姿态偶然性。
3. 按样本汇总文本、音频、视觉三个模态的 top-1 或 top-3 证据窗：在视频时间轴上绘制不同颜色的区间条，并在图注中标注 `impact_score`、秒数和帧号；视觉证据的关键帧应加边框或角标，音频证据以波形/时间轴高亮表达，文本证据展示原始转写及其“aligned relative window”时间代理属性。
4. 将样本级预测（`pred_class`、`pred_regression`）、模态级反事实贡献、局部窗口影响和原始帧组成一张解释卡。解释卡应明确写出“附件四无标签”“反事实遮挡敏感性，非因果真值”“文本时间为相对窗口映射”，避免把模型输出伪装成人工事实。
5. 选择样本时预先固定规则，例如：附件四每条样本均生成机器可读卡；论文主文仅展示贡献高度集中、三模态相对均衡、预测强度接近零等不同模式的代表样本。选择规则、所有候选样本及未展示原因均写入汇总表，防止只挑选有利案例。

## 4. v6 应形成的输出体系

为与项目的时间戳输出规范一致，建议新目录至少包含以下文件，而不修改原始训练目录：

| 文件/目录 | 内容与作用 |
| --- | --- |
| `run_config.json` | 源运行目录、特征哈希、样本选择规则、帧提取规则、OpenCV 版本、颜色/排版参数与随机种子（如涉及抽样） |
| `source_manifest.json` | 源 CSV、源 checkpoint 配置与 MP4 的路径、大小、SHA-256；保证图表可追溯 |
| `video_decode_audit.csv` | 每个附件四视频的实际 FPS、容器帧数、实际解码帧数、尺寸、证据帧是否越界及处理规则 |
| `explanation_summary.csv` | 每个样本的预测、三模态贡献、主导模态、top 证据窗、映射状态和卡片路径 |
| `evidence_cards/` | 每个附件四样本的 PNG 解释卡；文件名与 `sample_id` 的安全编码一一对应 |
| `keyframes/` | 按样本、模态、rank 保存的原始或带标注关键帧，便于人工复核 |
| `fig_global_contribution.png` | 附件四样本的模态贡献分布；只描述模型内部敏感性，不带性能结论 |
| `fig_fidelity_valid.png` | 沿用有标签验证集的高/低证据遮挡诊断，并标注样本数 32 与非因果边界 |
| `table_evidence_examples.csv/.tex` | 代表样本的预测、贡献、证据秒数/帧号与解释文本，供论文直接引用 |
| `anomalies.csv` 与 `output_checksums.json` | 映射、解码、写图异常及全部输出摘要，避免静默漏图 |
| `README.md` | 文件字段、解释边界、复现命令、人工抽检步骤和不能作出的结论 |

其中 `keyframes/` 与解释卡是 v6 相比当前数值解释的关键增量。单张图既要有可感知的原视频依据，也要保留能机器读取的 CSV 证据；仅保存截图、没有帧号和源文件哈希，不能满足可核验性要求。

## 5. 评价、论证与论文表达

可解释性的论证应分为四类，不能用单一漂亮图像代替：

1. **预测有效性**：复用固定模型的 valid/test Accuracy、Macro-F1、MAE、Pearson，并在表注中说明 test 未参与模型选择。当前指标是单种子结果，属于基线证据，尚不支持“显著优于”其他模型的结论。
2. **忠实性**：报告验证集高/低证据窗口遮挡影响及其差异；后续应补充删除曲线、插入曲线，至少比较窗口长度 3/5/7 与零值无效遮挡、训练集均值替代两类基线。只在 valid 上确定解释规则，test 用于固定规则后的诊断。
3. **稳定性**：比较不同窗口、遮挡基线和至少多个固定随机种子的主导模态、top-k 窗口重叠率。若主要证据不稳定，应如实报告，不应只展示某一设置。
4. **可回溯性**：统计附件四证据记录中 `source_exists`、`mapping_status`、成功解码率、帧越界率和解释卡生成率；论文中展示的每一个关键帧均应能由 `sample_id + modality + rank + frame_start/frame_end` 重新定位。

建议在论文中采用如下专业表述：动态门控仅反映融合层的内部权重；完整模态遮挡后的归一化影响定义为“模态级预测敏感性”；局部窗口遮挡后的影响定义为“时序证据强度”；视频关键帧仅是该时序证据区间的可视化锚点。应避免使用“证明该模态导致情感”“模型发现真实情绪原因”“附件四准确率”等超出数据与方法边界的说法。

## 6. 风险、依赖与验收条件

第一，aligned 50 个位置是题给特征的统一时间轴。附件四文本证据当前使用的是 `raw_text; aligned relative window`，不是逐词强制对齐时间戳；文本卡片必须显式披露其为相对时间代理。第二，`frame_start/frame_end` 当前按视频时长比例计算，v6 应重新以 OpenCV 解码结果复核，不应只相信容器头帧数。第三，附件二验证样本未必都有附件四那样的可用视频，因而视频可视化的主对象应是附件四；有标签解释质量诊断仍应在验证集完成。第四，反事实遮挡可能引入分布外输入，需把基线选择和敏感性分析作为局限性记录。

本版本的验收不应以“生成了若干图片”为准，而应同时满足：

- 所有新产物存放在新的时间戳子目录，源训练运行及原始视频均未被修改；
- 每张解释卡均能追溯至一个 `sample_id`、一个映射 CSV 行、一个源 MP4 和明确的帧区间；
- OpenCV 解码审计、缺失源视频和帧越界处理均有机器可读记录；
- 全局图、样本卡、CSV/LaTeX 表和 README 对“模型敏感性而非因果真值”的边界保持一致；
- 附件四始终未进入训练、参数选择、阈值选择或性能统计；
- 图表的源运行目录、输入哈希和脚本版本均可在清单中复核。

因此，v6 的合理推进顺序是：先冻结上述最新运行并生成只读来源清单，再完成 OpenCV 解码审计与解释卡，随后完成全局统计图和忠实性/稳定性诊断，最后由人工抽检若干“CSV 证据 - 视频时间段 - 关键帧”闭环。未完成视频解码审计、稳定性分析与人工抽检前，当前结果只能称为“可回溯解释原型”，不能称为经过充分验证的最终可解释性方案。
