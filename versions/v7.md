# 版本分析

## 1. 审查对象、题目要求与判定口径

本版本审查的对象应区分为两类：其一是完整训练、验证、测试和附件四推理运行 `E-q/q_3_output/20260925_100021_726334600/`；其二是从该运行只读生成的视频级解释材料 `E-q/q_3_output/20260925_204345_016423900/`。后者是解释产物，不是训练运行，不能因为其时间戳最新就将其误认为新的模型训练、验证或测试结果。正式论文应把前者作为预测性能和权重来源，把后者作为附件四视频可视化与可追溯证据来源，并在来源清单中建立二者的显式关联。

已核对 `E-q/复杂场景下多模态情感识别的数学建模与算法设计.docx` 的问题三原文及“结果与提交说明”。问题三要求模型同时输出情感极性、情感强度、主要参考模态、模态作用程度和可回溯的局部证据；证据必须对应原始文本、语音时间段或视觉关键帧。论文还必须呈现：(1) 建模原理、网络结构、目标函数、训练方案和参数；(2) 典型样本解释卡；(3) 主要参考模态内的局部片段重要性分布，以及三模态作用差异；(4) 附件四全量预测与解释汇总；(5) 验证集性能、可视化分析与错误归因。附件四无标签，只能用于最终推理和解释，不能参与训练、模型选择、阈值选择或真实性能统计。

本审查遵循以下原则：以题给文件、运行配置、代码逻辑和可重算输出为事实来源；将“模型敏感性”与“真实情感原因”严格区分；把未能由当前输出直接复核的事项标记为待整改，不以已有图片数量替代可解释性质量。

## 2. 当前流程与建模方案审查

### 2.1 已实现且可复核的主流程

当前主训练运行固定使用附件二 `aligned_50.pkl`，哈希为 `66e867aa74bc70a844e806e5571e371c9abb4a35f9e2887ce9b4d97ff2cb8fcd`，输入规模为 train/valid/test=3395/728/727，三模态维度为文本 768、音频 74、视觉 35，输入接口和附件四保持 aligned 版本一致。训练集独立拟合标准化参数，模型为掩码感知的模态投影、模态内 Transformer 编码、文本查询音频/视觉的跨模态注意力、动态门控融合和分类/回归双任务头。`src/q_3/model.py` 对 padding mask、全缺失模态和掩码平均池化已有显式处理，现有单元测试覆盖标准化、非有限特征、缺失模态和反事实解释的基本契约。

完整运行完成 50 个 epoch、2700 个优化步，保存了 `best_model.pt`、训练日志、训练集标准化参数、配置、输入摘要、验证/测试逐样本预测、指标、解释表、映射表、审计与输出哈希。运行摘要中的 valid 指标为 Accuracy=0.6071、Macro-F1=0.5476、MAE=0.6521、Pearson=0.5810；test 指标为 Accuracy=0.6726、Macro-F1=0.5950、MAE=0.6794、Pearson=0.6259。这些是单种子、固定模型后的当前结果，不足以支持显著性或优越性结论。

附件四已有 20 条全量预测行和每模态 top-3 局部证据映射；每个映射行包含时间索引、影响分数、秒数、帧区间、FPS、源视频、文本证据与映射状态。视频解释运行已使用 OpenCV 实际解码 20 个 MP4，生成 60 张无文字覆盖的原始关键帧、20 张纯画面解释卡，以及以文件名为键的 `keyframes.json`、`evidence_cards.json`。因此“输入特征 - 预测 - 证据窗 - 视频帧”的机器可读链条已具备原型。

## 3. 代码审查发现与必须整改项

### P0：解释参数选择与附件四输出不一致

`20260925_100021_726334600/run_config.json` 中附件四证据由 `zero_invalid`、`explain_window=5`、`explain_stride=5`、`top_k=3` 产生；而 v6 在完整验证集 728 条样本上选择的是 `train_mean`、window=7、stride=7。当前 `q3_complete_explainability.py` 仅用选出的参数做验证集诊断，却仍读取原运行的 `predictions_attachment4.csv` 和 `evidence_mapping_attachment4.csv` 来画图、抽帧和建卡。因此，解释卡、关键帧、全量附件四解释文件与“已选择解释参数”不一致，不能同时作为同一最终方案的证据。

整改要求：将解释基线、窗口、步长、top-k 作为 `cli/q3_run.py` 的显式运行配置；在验证集固定选择后，使用同一 checkpoint、同一训练集标准化参数和同一组解释参数对 valid/test/附件四重新执行解释；新目录必须输出配置、完整映射、全量附件四预测、全量附件四解释、选择来源哈希和审计。v7 最终性能/解释材料只能引用该统一运行目录。

### P0：`train_mean` 基线存在双重标准化尺度错误

`scripts/q3_complete_explainability.py` 的主函数已将 train/valid 通过 `apply_standardizer` 变换；但 `validation_diagnostics` 又对传入的 `train` 调用一次 `apply_standardizer(train, stats)` 后再计算 `modality_means`。这使“训练集均值基线”并非训练集标准化空间中的正确均值，选出的 `train_mean + window=7` 及其忠实性数值均可能受错误尺度影响。

整改要求：只对原始训练特征标准化一次，或对已标准化的 `train` 直接按有效 mask 计算均值；将三模态均值、有效位置计数和基线空间（raw/standardized）写入输出。修复后必须重新执行完整验证集参数比较，不能沿用当前选择结果。

### P1：训练 CLI 与解释模块的接口未统一

`src/q_3/explain.py` 已支持 `baseline` 和 `modality_means`，但 `cli/q3_run.py` 的训练、附件四纯推理和 `make_explanations` 尚未暴露该参数，仍默认调用零值无效遮挡。解释器的新能力不能由主 CLI 复现，导致 README、模型检查清单和实际可执行流程不一致。

整改要求：在 CLI 增加 `--explanation-baseline`，在 `train_mean` 情况下从训练阶段保存/加载均值基线；将基线、均值文件哈希和窗口配置写入 checkpoint 关联配置、`run_config.json`、`run_summary.json` 和映射 CSV 的 `explanation_baseline` 字段。

### P1：局部证据、可视化和错误归因尚不完整

当前解释器只导出每模态 top-k 非重叠窗口，而没有导出全部滑动窗口分数；`fig_fidelity_valid.png` 读取的也是原训练目录中 32 条验证样本、window=5、零无效遮挡的旧汇总，而非 v6 完整验证集或最终选择配置的结果。`table_evidence_examples.tex` 固定取样本编号前六条，不能代表“主要参考模态、预测强度和解释差异”的预先定义代表性选择。`evidence_cards/` 已按用户要求保留原始画面，但元数据被移至 JSON，论文中仍需结合旁侧表格或时间轴显示预测、贡献、时间和影响量。

整改要求：导出 `local_importance_<split>.csv` 的全部窗口分数；生成典型样本的三模态时间轴/热图、主要模态局部重要性曲线、门控与反事实贡献一致性图、验证集混淆矩阵、回归残差图和错误样本表。代表样本应由预先记录的规则选择，例如文本主导、视觉主导、贡献均衡、分类错误、回归绝对误差最大各一条，并记录候选集合与选择理由。

### P1：视频映射异常和解释精度需单独量化

附件四 20 个视频均可打开，但 `video_decode_audit.csv` 显示多数容器帧数与实际顺序解码帧数不一致，当前至少 15 个 rank-1 证据帧被截断到最后可解码帧。此时 `frame_start/frame_end` 仍来自容器时长比例映射，截断画面只能视为“可回看近似锚点”，不能作为完全精确的视觉证据定位。

整改要求：输出映射完整率、帧区间越界率、截断率和每模态受影响样本数；对截断样本优先以实际解码时长重新映射时间窗，或在最终解释 CSV 中增加 `mapping_precision=approximate_after_decode_clamp`。文本证据须持续标明 `raw_text; aligned relative window`，不得描述为逐词时间戳。

### P2：训练与审计的工程化缺口

当前 `validation_audit.json` 验证了划分主键、标签、数值有限性和附件四仅推理，属于必要基础检查；但没有针对输出行数、附件四 sample_id 覆盖、贡献和是否为 1、证据窗口边界、源视频可用率、解释参数一致性、哈希重算和依赖版本的端到端审计。训练运行也未输出 `requirements`/依赖版本快照和输入文件清单。现有测试仅覆盖 5 个核心单元契约，未覆盖完整训练、checkpoint 纯推理、CSV 安全前缀往返、视频映射异常和解释参数传播。

整改要求：新增 `q3_audit.py` 或等价模块，自动生成审计报告并在失败时非零退出；新增上述关键路径单元/集成测试；在正式运行目录保存 `environment.json`、`input_manifest.json`、数据/权重/标准化/视频哈希和生成脚本版本。

## 4. v7 整改后的端到端流程

v7 不应仅在历史输出上叠加图表，应形成一次闭环、同配置的正式运行：

```text
固定 aligned 特征版本、随机种子和附件二 train/valid/test 边界
        -> 仅用 train 拟合标准化、类别权重和 mean 基线统计量
        -> 训练双任务模型，按 valid loss 固定 checkpoint
        -> valid：比较解释基线/窗口，并输出完整局部窗口分数与忠实性诊断
        -> 固定解释参数，重新解释 valid/test；test 只报告固定配置结果
        -> 附件四：只加载固定 checkpoint 与训练统计量，输出全量预测和同配置解释
        -> OpenCV 解码、实际时长映射、异常审计、原始关键帧与 JSON 元数据
        -> 生成论文图表、LaTeX 表、错误归因表、来源清单和总审计报告
```

正式运行应将预测模型输出与视频解释输出写入同一个新的时间戳父目录，或在两个时间戳目录之间以不可变 `source_manifest.json` 明确引用；无论采用何种组织方式，都必须保证附件四的 `predictions_attachment4.csv`、`evidence_mapping_attachment4.csv`、关键帧 JSON、解释卡 JSON 和图表使用同一 checkpoint、同一标准化文件、同一解释基线与窗口配置。

## 5. 验收标准与当前结论

v7 审查通过的最低条件为：

- 题目问题三规定的五类论文内容均有对应、可追溯的结果文件；
- 训练、验证、测试、附件四边界经自动审计通过，附件四未参与任何选择；
- 解释参数由修复后的完整验证集选择，并在附件四全量输出中一致使用；
- 全部附件四样本均有预测、三模态贡献、主要模态、局部证据和可复核源素材引用；
- 视频解码/映射异常均量化、列出并影响最终解释精度表述；
- 关键图、表、JSON、CSV、checkpoint、标准化参数、输入哈希、环境版本和审计报告可由脚本重建；
- 解释文本严格使用“模型敏感性/预测证据”而非因果或无标签性能表述。

截至本次版本分析，当前问题三实现具备可运行的预测与解释原型，也保留了较完整的训练和视频审计材料；但因 P0 的尺度错误和最终解释配置不一致，尚不能判定为“审查通过”，更不能将现有附件四解释卡作为最终提交版本。应先完成 P0、P1 整改，再按上面的闭环流程从训练、验证、测试到附件四推理重跑一次，最后再进行 v7 的终验与论文材料固化。
